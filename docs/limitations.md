# Limits and gotchas

What the API cannot do, and the reasons behind the design.

## You cannot author a fish prefab from scratch

This is the constraint everything else follows from.

`Item`, `Creature` and `NetworkObject` carry code generated by **FishNet at the
game's build time**. `Item` alone has twelve generated members:

```
NetworkInitialize___EarlyCreatureAssembly_002DCSharp_002Edll_Excuted
RpcWriter___ObserverHit___701300449
RpcReader___...
```

FishNet runs an IL post processor over every `NetworkBehaviour` when the game is
compiled. A prefab authored in your own Unity project cannot carry those
components, because the generated methods only exist inside the game's compiled
assembly and your project cannot produce them. Script references also bind by
GUID into that assembly.

So MoreFishAPI clones one of the game's own creatures at load time and grafts
your artwork onto it. I believe this is the only way to get a functioning networked fish.

## You cannot make a fish hostile

Same reason. `AttackingFish` extends `Fish` extends `Creature` and carries
fourteen generated members, so it cannot be added to a clone at runtime.

`Hostile = true` logs a warning and does nothing. A hostile fish means choosing a
hostile template. See [Templates](templates.md) for the ten available.

`Hostile = false` does work, and neutralises an attacking template.

## There are only 256 item ids

The game stores item ids as a **byte**, and vanilla already uses many. Custom
fish are allocated ids in the range 128 to 250, so exactly **123** custom fish
can exist across all installed fish mods at once.

Ids are derived purely from a hash of your `Id` string, so the same fish gets the
same id on every machine that has the same set of fish mods installed. Nothing is
looked up or remembered to decide this, which is what makes it agree across
players without any negotiation.

`MoreFishAPI/fishids.json` records what was assigned last time, but only to warn
you when an id changes. It is a record, not the source of truth.

Ids can still shift. If two fish hash to the same slot, the second one probes
forward, so installing or removing an unrelated fish mod can move your fish. The
log warns whenever that happens.

**Consequence: never rename a published `Id`.** It orphans every one already
saved.

Id 255 is reserved. The game uses `byte.MaxValue` internally to mean "the boat".

## Everyone in a lobby needs the same fish mods

A player without your mod will not see your fish. It appears to them as nothing
at all rather than as some other fish, because the network prefab list is seeded
by item id: slot 102 means id 230 on every machine, and unclaimed slots hold
invisible placeholders.

To check two players match, compare the checksum each logs at startup:

```
Fish set checksum B40F1DCF. Everyone in a lobby must show the same checksum, or fish will not match.
```

Same checksum means the fish sets agree. Different checksums mean somebody has a
different set of fish mods, or an id collided and shifted.

Host mode hides all of it. Testing solo will never surface a mismatch.

## Removing a fish mod

Saves containing a custom fish are handled. The game's own inventory loader
stops at the first unknown item id and silently drops everything after it,
including your remaining items and all purchased bait. MoreFishAPI intercepts
that and strips unknown items first, so the rest of the inventory survives.

The lost item is still lost, but only that one.

## Journal side effects

Custom fish appear in the journal by default. They also count toward the game's
"catch everything" achievements, so a custom fish that is impossible to catch,
because its `BaitFilter` matched nothing or its rarity is zero, makes those
achievements unobtainable while the mod is installed.

Set `InJournal = false` if your fish is meant to be unobtainable.

The same applies to shinies, and it is easier to trip over. The game's catch
every shiny check walks every creature not excluded from the journal and requires
a shiny of each. A fish with `InJournal = true` and `AllowDrip = false` is in that
list but can never roll a shiny, so the check can never pass while your mod is
installed. Registering that combination logs a warning. Set `AllowDrip = true`, or
keep the fish out of the journal.

Custom fish appear after the bosses on the last journal page, because the game
sorts that list once at startup and custom entries are appended afterwards. This
is cosmetic.

## Registration is one shot

Fish must be registered from `Awake`. Item ids and the network prefab list are
assembled once, shortly after the game's own item list is ready.

A fish registered after that is **refused**. `Register` returns `false` and logs
an error naming your mod, rather than accepting a fish that could never appear.

## Things inherited from the template

Anything not set is inherited, and templates vary a lot. Health ranges from 5 to
1000 across them. Several are flagged endangered. Skin presets, sounds, cooking
behaviour and weight distribution all come from the template.

Set `Health` and `Endangered` explicitly unless you have checked what your
template carries.

## Not exposed yet

Cooking behaviour, quest eligibility, custom sounds, localised names, custom
bait, depth or location based spawning, and boss fish are all unexposed. Some are
feasible and some are blocked by the same codegen wall.
